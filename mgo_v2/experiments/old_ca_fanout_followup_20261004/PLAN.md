## 2. Policies

### BR

Use the current Balanced Random baseline unchanged. Keep the same balanced
mandatory-miss quotas used by all policies.

### Current-CA

Use the current clean CA unchanged:

```
maximize sum_e,r demand[e,r] * x[e,r]
```

under the same balanced quota slots. This primarily maximizes local
expert-routes.

### OldCA-fanout

Port the **exact communication term** from original runtime commit
`a0be82e`, `mgo_v2/mgo_v2/admission.py::_incremental_cost` and
`HungarianAdmission`.

For an incoming expert `e` and candidate rank `r`, define:

```
cost(e,r) =
  number of tokens t using e such that
    r != origin_rank[t]
    AND
    r is not already a destination of t through a pre-owned resident expert
```

Then solve the balanced Hungarian assignment over the same quota slots as BR
and Current-CA.

Important implementation fidelity:

- `base_destinations[t]` contains destinations created by **pre-owned resident
  experts before the new admissions**.
- For the Hungarian matrix, do NOT mutate this base as other incoming experts
  are assigned. This reproduces the old linearized objective rather than a new
  greedy/exact nonlinear fan-out solver.
- Keep deterministic expert ordering and quota-slot construction.
- Do not enable old same-layer/path affinity bonuses in this first study.
- Do not change eviction, substitution, cache capacity or fetch quota.

Call this policy `OldCA-fanout`, not an exact global fan-out oracle.

## 3. Why this is different from Current-CA

Current-CA rewards each local expert-route independently.

OldCA-fanout instead asks whether placing expert `e` on rank `r` introduces
a **new destination rank for a token**. Multiple experts already served on the
same destination do not require another hidden-state dispatch.

Primary mechanism metric:

```
fanout_event = sum_t number_of_distinct_remote_destination_ranks(t)
Fanout_total = sum_events fanout_event
```

Also retain aggregate peer bytes and the existing per-event critical-rank
metric. Do not treat them as interchangeable.

## 8. Interpretation

Primary diagnostic:

- If OldCA-fanout improves TPOT more than Current-CA while reducing fan-out more,
  this supports the hypothesis that token->rank communication geometry matters
  more than aggregate peer-byte volume.
- If both reduce communication counters but neither improves TPOT, the old
  runtime's historical speedup likely depended on other coupled effects
  (controller, affinity, cache trajectory, collective implementation).
- If OldCA-fanout only works with a material H2D reduction, do not attribute the
  timing gain purely to communication.

The historical a0be82e numbers are context only, not a target to reproduce.
