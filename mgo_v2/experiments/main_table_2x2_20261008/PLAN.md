# Two-model, two-dataset R4 main table

Owner scope: R4 on physical GPUs 0,1,4,5; C30 expert-residency budget; ShareGPT and the local official LMSYS-Chat-1M Parquet shards; Qwen3-30B-A3B-Instruct-2507 and DeepSeek-V2-Lite-Chat; input 512/1024; local batch 16/64. Four systems per workload: selected main_OURS, repaired MoE-Infinity, DeepSpeed ZeRO-Inference CPU parameter offload, and synchronous llama.cpp with balanced expert placement. There are 16 workload cells and 64 system-cell rows.

Carry forward the existing headline timing contract unless a model-specific compatibility check requires an explicit, documented change: BF16, greedy ignore-EOS generation of 64 output tokens; disjoint warmup and target request batches; clear dynamic expert cache after warmup; three clean target repeats with median TTFT, TPOT, and E2E plus full ranges. TPOT includes attention. Report the C30 expert budget, actual peak HBM, pinned host memory, and per-system run receipts. Do not trim timing outliers or mix earlier H0/prefetch-ON results into the new table.

Select distinct conversations in source order with a final user turn, render each model's own chat template, and take the last exact 512 or 1024 tokens only when the rendered context is long enough. Freeze separate model-specific token-ID manifests before timing; all four systems for one model/dataset/batch/input cell consume the same manifest. Never commit raw LMSYS prompts or token-ID manifests; keep only hashes, counts, eligibility rules, source-file identity, and timing summaries in Git.

Qwen OURS uses the owner-selected main_OURS configuration: native C++ expert executor, optimized prefill/decode index paths, Near placement, rank-private full-pinned CPU expert source, BF16 partials, prefetch OFF. The three baselines keep the existing audited Qwen C30 implementations. The llama.cpp Qwen baseline must use the selected synchronous 32-thread, CUDA-graphs-OFF, graph-reuse-OFF balanced3 expert placement and check physical device counts 3/3/3/3 on every run.

DeepSeek-V2-Lite is a different model family (27 layers, 64 routed experts, top-6, shared experts, MLA). Do not relabel the Qwen-only 48-layer/128-expert OURS runtime as DeepSeek. Port and validate model loading, expert layout/cache byte size, shared-expert execution, rank routing, output numerics, attention/KV, and C30 budget before its first measured run. DeepSeek llama.cpp requires a local BF16 GGUF converted from the specified HF checkpoint and an audited model-specific balanced placement; the Qwen balanced3 layer IDs cannot be reused blindly. Adapt each baseline only as needed, preserving its core algorithm and recording version/changes.

Execution order: (1) source/model/weight/budget preflight and manifest freeze; (2) Qwen small-cell smoke for all four systems, then full Qwen table; (3) DeepSeek per-system correctness and budget smokes, then full DeepSeek table; (4) aggregate only fully validated rows. Run one GPU job at a time on 0,1,4,5 with the existing 384-GiB host preflight, 96-GiB stop guard, and per-process HBM bound. Preserve failed attempts, repair reproducible errors, and resume incomplete cells. Do not use GPUs 2,3,6,7.
