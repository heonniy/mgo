# EP timing metric correction

The initial preview placed clean end-to-end TPOT next to a non-attention MLP span from a **different instrumented execution**. For C30/env2/B8 case0 BR, clean TPOT was 0.451557 s/token, while the diagnostic execution's own total TPOT was 0.500436 s/token. Therefore the old non-attention value of 0.465817 s/token could exceed clean TPOT without representing an impossible within-run decomposition. It also selected the rank with the largest MLP span, which could differ from the rank determining full step latency.

An intermediate audit summed exclusive expert and dispatch/return scopes on each step's slowest complete-phase rank. That established that the new EP scopes do not double-count nested spans. The final metric below uses those same scopes on the **last-return rank per layer** and adds the cross-rank arrival tail. Clean full TPOT remains the primary performance result and includes attention. No model rerun is needed: all corrections derive from preserved rank-level diagnostic segments and boundary timestamps. The reporting script validates that the sum of phase spans matches diagnostic wall TPOT within 1%.

The final requested metric is **EP critical-path latency**. For each of the 48 decode layers, it starts when the first rank enters forward dispatch and stops when the last rank completes return/combine. The 48 layer windows do not overlap in the validated trace, so their durations sum to one per-token EP critical-path time. The compute and dispatch/return columns sum exclusive spans on the last-return rank; the remaining window time is rank arrival/other. The shared release clock anchors rank stream spans, and stream-span-to-wall residuals are below 1 ms. This per-layer construction excludes the attention/controller intervals *between* layer windows, but can include late-rank attention, metadata, H2D dependencies, and peer waiting *inside* a window. It is therefore an EP-path latency, not pure kernel or wire time.

For C30/env2/B8 case0 BR, the intermediate per-token audit found clean full TPOT **0.451557** s/token, paired diagnostic full TPOT **0.500436** s/token, and EP layer windows **0.335898** s/token (= expert execution **0.217371** + dispatch/return **0.104155** + rank arrival/other **0.014373** s/token). The original 0.465817 non-attention value is retained only as historical context in the raw diagnostic receipt.

The final table additionally follows the user's requested **single whole-decode interval**: first dispatch of decode step 0 through last return/combine of decode step 31. Its units are seconds across all 32 steps. This envelope is almost the full diagnostic decode because it also includes all attention/controller/H2D between layer windows. The separate EP-layer-window sum, compute, dispatch/return, and arrival/other totals are also shown in cumulative seconds across 32 steps; only clean TPOT uses ms/token.
